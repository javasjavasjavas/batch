## Steam asset generator

`/app/steam` (also `/tools/steam-assets`) provides 15 Steamworks raster presets,
individual crop/fit controls, optional transparent logo overlays, and separately
uploaded gameplay screenshots. Files are processed locally. The ZIP includes
named images, a readable guide and a JSON manifest with dimensions and sources.

Library Hero uses separate text-free artwork for the Emberfall sample. For custom
uploads, “Remove text / logo” opens a local Tesseract text detector and editable
rectangle masks. LaMa inpainting runs in a dedicated worker, with a pinned model
download cached by the browser. Users preview and apply the result only to the
Hero. Stylized lettering and symbols may need manual selection; large repairs
can soften detail. Cancel terminates processing and preserves the source.
Model and library attribution: `public/ai-credits.txt`.

Specifications are recorded in `src/data/steamAssets.ts`, checked against the
official Steamworks documentation on 2026-10-20. Content, legibility and crops
still require review; one artwork cannot replace a transparent logo or real
gameplay screenshots. macOS ICNS icons are outside this raster export tool.

Run `npm test` and `npx tsc --noEmit` to verify the processing and application.

## Cloudflare deployment

The application is a React/Vite site with prerendered public pages and client-side image workspaces. Image processing, AI inference, and
ZIP generation run in the visitor's browser; no API server or database is needed.

Connect `javasjavasjavas/batch` to Cloudflare Pages:

- Project name: `batchimagekit` (matches `wrangler.json`).
- Production branch: `main`.
- Framework preset: React (Vite).
- Build command: `npm run build`.
- Build output directory: `dist`.
- Root directory: repository root.
- Node.js: 22, declared in `.node-version`.

Cloudflare installs dependencies from `package-lock.json`. The Wrangler config
declares `dist` as the Pages output. The build prerenders public pages and every
supported workspace route to extensionless HTML pages. A top-level `404.html`
gives unknown URLs a real 404 response. Generated `_redirects` redirect platform
`/app/:id` aliases to `/tools/:id-assets`. Canonicals consistently use
`https://batchimagekit.com`. Host redirects are configured in Cloudflare Bulk
Redirects: list `batchimagekit_canonical_hosts`, enabled rule
`Batch Image Kit canonical domains`. Both `www.batchimagekit.com/` and
`batchimagekit.pages.dev/` redirect permanently (301) to the canonical origin,
preserving path suffixes and query strings with subpath matching enabled.
Include subdomains is disabled so deployment preview hosts remain independent.
These account-level settings are managed in Cloudflare, not deployed from this
repository; Pages `_redirects` does not support host-level sources.
No Functions, Worker script, or paid storage is needed.

Live URLs:

- https://batchimagekit.com/
- https://www.batchimagekit.com/ (301 to the canonical domain)
- https://batchimagekit.pages.dev/ (301 to the canonical domain)

The project uses Cloudflare Pages Free. Both custom domains are associated with
the Pages project and have proxied CNAME records pointing to
`batchimagekit.pages.dev`. Namecheap delegates DNS to
`julissa.ns.cloudflare.com` and `todd.ns.cloudflare.com`; manage future DNS
changes in Cloudflare. Existing email MX and SPF records are preserved.
HTTPS and the HTTP-to-HTTPS redirect were verified on 2026-10-21.
Repository pushes to `main` trigger automatic builds and deployments.

AI models are downloaded on demand from their configured external model hosts.
Keep these model files outside the static asset bundle: individual Cloudflare
static assets have a 25 MiB limit. The browser caches downloaded models.

## Search visibility

Run `npm run build` to build browser assets, render static HTML, generate
`sitemap.xml`, `robots.txt`, redirects and cache headers, and audit the output.
`npm run test:seo` repeats the output audit after a build.
Run `node scripts/check-live-seo.mjs` after deployment to verify public pages,
workspace exclusions, aliases, HTTP/HTTPS host redirects, sitemap and real 404s.
It also verifies the deployed titles/descriptions and social image dimensions.
Run `node scripts/build-search-preview.mjs` after a build to regenerate the
local search/social preview in `docs/search-preview.html`.

Help illustrations are real cropped screenshots of the bundled sample batch,
stored in `public/guides` and mapped to sections in `src/data/guideScreenshots.ts`.
Refresh these when the illustrated controls change; keep dimensions, alt text
and captions aligned with each screenshot. Images load lazily and can be enlarged.
The current benchmark, positions and implementation screenshots are in
`docs/adsense-benchmark-2026-10-21.html`. AdSense integration is prepared but
disabled until the publisher account, site approval and consent setup are ready.

`src/data/seo.ts` is the source of truth for public metadata, canonical URLs and
workspace exclusions. Add public routes there when adding a page. Tool, platform
and guide entries are generated from their content catalogs. The audit checks
unique metadata, one H1 and canonical, schema, discoverability, local links,
assets, workspace exclusions and redirects. Do not add a wildcard SPA rewrite: it
would turn unknown addresses into soft 404s. Existing workspace routes are built
explicitly so direct links and reloads continue to work.

Public content is rendered using the same React routes as the browser. Client
navigation updates metadata, and route code loads on demand. The browser keeps
the static page visible until its initial route is ready, then mounts the
interactive application with the visitor's local preferences. No image data is
processed or stored during prerendering.

Submit https://batchimagekit.com/sitemap.xml in the site's verified Google Search
Console and Bing Webmaster Tools properties. Sitemap discovery does not confirm
indexing. Track organic impressions, clicks and successful tool usage by landing
page; rankings and traffic improvements require live search data.

## AdSense activation

`src/config/advertising.json` is the public configuration. IDs are public ad
identifiers, never credentials. Keep `enabled: false` while setting up the account.

1. Choose the owner's AdSense account, add `batchimagekit.com`, and complete its
   requested ownership verification and site review. Add the actual `ca-pub-...`
   ID to `publisherId`: the build then generates `ads.txt` and the verification
   meta tag even while ad serving is disabled. Deploy and verify both live.
2. Finish the public Privacy/Terms pages with the operator's chosen public
   identity and contact. Publish and verify Google's consent messages in
   Privacy & messaging for the regions served, including an accessible refusal
   and revocation flow. Only then set `consentMessagePublished: true`.
3. Keep Auto ads off initially (including anchors, side rails and vignettes),
   so ads stay in the reviewed manual placements. Set
   `manualPlacementsConfirmed: true` only after checking the account setting.
4. Create 12 Display ad units using responsive sizing, named after the keys in
   `units`: home-primary, home-secondary, tool-primary, tool-secondary,
   platform-primary, platform-secondary, workspace, results, directory,
   guide-rail, guide-inline and help. Enter each real numeric slot ID. Shared
   templates reuse units; page-family/device reports distinguish their traffic.
5. Once the site is approved and consent verified, enable the configuration,
   build and deploy. Check fill, consent choices and Active View on the canonical
   domain without clicking your own ads. Account review can take time; valid IDs
   and a successful build do not prove approval or ad delivery.

The build rejects incomplete enabled configurations. Once the published CMP and
manual-only settings are confirmed, the SDK can load for consent management while
`enabled: false` still suppresses all ad slots during site review. The SDK is restricted to
the canonical domain and www. Manual slots exclude legal, review, processing and
error screens. Each slot requests once near the viewport; there is no timed
refresh. Workspace reserves a separate row only on screens at least 1280 × 700.
Google's published CMP manages ad consent; the old local preferences do not
authorize Google ads. The SDK remains available on legal routes for privacy
choices, which is why manual-only account configuration is required.

Run the development server and append `?ads=preview` to inspect reserved spaces
without any real Google ad requests. This preview is absent from production.
When disabled, ad slots and their reserved space are omitted.

## Traffic measurement and Search Console

Google Analytics 4 uses web stream `G-9KF9E5Y7MW` (Batch Image Kit — Web).
Settings live in `src/config/analytics.json`. Only the production domains collect
analytics; localhost and preview deployments do not. Keep enhanced measurement
OFF in the Google UI: page views are sent once per React route change, and the
app explicitly sends `batch_start` and `asset_download`. Download events indicate
that a download was initiated, not that a browser saved the file successfully.

Analytics is opt-in through its own versioned 180-day consent choice, separate
from AdSense's Google CMP and the old prototype preference. The footer permits
revocation. No image, filename, batch title or form value is sent. Page paths are
allowlisted; query strings and fragments are removed, and external referrers are
reduced to their origin. Google signals and ad personalization are disabled in
the tag configuration. Tests cover consent, revocation, URL privacy and duplicate
page views. Account data-sharing options were left disabled.

The Search Console verification meta tag in `index.html` belongs to the
`https://batchimagekit.com/` property under the owner's Google account. Preserve
it during future redesigns. Submit `https://batchimagekit.com/sitemap.xml` in that
property; indexing status must be checked in URL Inspection, not inferred from
a successful deployment or a search engine site query.
